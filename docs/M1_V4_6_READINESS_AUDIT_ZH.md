# M1 v4.6 实验就绪审计补充

审计日期：2026-08-27  
相对版本：M1 v4.5 → M1 v4.6

## 1. 本次设计变化

v4.6 删除了六种资产第一次出现时的默认分界点。每个资产的 G0 页面现在遵循同一流程：

1. 主图开始时没有分界线，不再显示 1/3、2/3 的预设位置；
2. 参与者在主图上点击两个不同的观测位置；
3. 系统按时间位置自动排序并从左到右编号；
4. 第一条边界放置后仍保持统一底色；若第二次点击落在同一观测位置，界面要求重选而不会自动移动；
5. 两点都放置完成后，才显示两个不确定范围旋钮；
6. 提交仍要求恰好两个分界点和两个已确认范围。

GI1–DI4 不受这一变化影响：当前可编辑位置仍继承同一资产上一层的答案，上一层位置仍用橙色虚线显示。这是“修正轨迹”设计的一部分，而不是外部默认锚点。

## 2. 版本和数据解释

- 会话协议：`m1-human-main-v4.6-blank-baseline`
- 响应格式：`v4.6-blank-baseline`
- 基线放置协议：`blank-two-click-placement-v1`
- 不确定范围协议：`continuous-range-knob-zero-enabled-v2`

v4.5 与 v4.6 不应在不控制版本的情况下合并分析。v4.5 的 G0 位置可能受 1/3、2/3 初始值影响；v4.6 的 G0 是测试者主动产生的点。

## 3. 已解决的审计问题

“G0 默认三等分造成初始位置锚定”已解决。当前 G0：

- 没有可直接提交的默认边界；
- 不会在测试者作答前把曲线划成三个等宽色块；
- 第一条边界放置后也不会提前以阶段色块提示第二条边界；
- 每个资产都要求两次主动位置输入；
- `adjustment_count` 会包含两次初始放置交互；
- `first_move_ms` 表示第一次实际放置分界点的时间。

为防止分析时把初始放置误当成“修改”，`disclosure_state_json` 另存 `initialPlacementCount`、`revisionAdjustmentCount` 和本层首次边界交互的计时含义。

## 4. 仍然存在的主要限制

这一修改只解决初始边界位置锚定，不代表 M1 已达到正式确认性实验状态。正式采集前仍需处理：

- 未回答的不确定范围控件在出现后仍有视觉起始位置，需决定是否隐藏未作答滑块位置；
- 保持上一层答案不变需要额外勾选，可能使“不变”的操作成本高于“移动”；
- 影响评分在边界锁定前可见，且未点击的默认 3 必须按 `influence_touched=false` 视为缺失；
- DI3/DI4 的英文事件文本、日期、叙事中立性和信息剂量仍需人工复核；
- 服务端已经阻止 v4.6 会话写入错误响应版本，也禁止已完成会话新增答案；正式采集前仍需把每条响应的资产、顺序和披露状态逐项绑定到冻结计划；
- 固定披露顺序仍把新增信息与重复观看、练习和疲劳联系在一起；
- 刷新后已提交记录保留，但参与者不能恢复原会话继续作答；
- 手机端尚未完成真实触控测试。

## 5. 放行判断

| 用途 | 状态 | 说明 |
| --- | --- | --- |
| 开发团队桌面端完整走查 | GO | 可验证两次点击放置、42 页保存与导出 |
| 小规模受控可用性 pilot | GO | 重点观察点击理解、初始位置分布、时长与疲劳 |
| 用于主分析的正式人类样本 | NO-GO | 仍需完成事件材料、交互对称性与服务端计划校验 |
| 正式 Human–Agent 比较 | NO-GO | 还需统一运行计划、视口、模型元数据和页面访问约束 |

本轮 pilot 应确认六种资产 G0 的位置分布不再在 1/3、2/3 附近异常聚集，并检查参与者是否能在无需额外解释的情况下理解“两次点击放置”的流程。
