# Boundary Lab 第三版研究协议草案

## 1. 研究目标

本项目测量同一个判断主体在逐层获得语义信息时，对同一条时间序列的阶段结构做出多大、什么方向的修正，并比较这种“上下文弹性”在人类与多模态 LLM / Agent 之间是否存在系统差异。

核心并不是寻找唯一正确的阶段划分，而是把“判断如何随信息改变”本身作为被解释变量。

建议预注册三个主问题：

- RQ1：仅增加资产与指标身份，是否已经导致阶段边界移动？
- RQ2：真实坐标和事件语义分别带来多大的增量修正？
- RQ3：人类与 Agent 的边界移动幅度、方向、置信度更新及无变化概率是否不同？

## 2. 实验条件

第三版将研究条件拆为三个可锁定维度。

### 2.1 曲线指标

- 价格：美元价格序列；
- 活跃地址：每日唯一活跃地址数；
- Google 搜索热度：相对关注度指数。

建议正式实验把指标类型作为组间条件，以免同一参与者先看到价格后，反向推断匿名活跃地址或搜索热度曲线。若采用组内条件，必须随机化指标顺序，并加入足够的洗脱任务。

### 2.2 判断任务

- 固定双分界：恰好两个分界点，得到三个阶段；
- 自由分界：测试者选择 1–5 个分界点，得到 2–6 个阶段；
- 预设评价：展示两条固定分界，把曲线划为三个阶段，测试者以 1–5 评价合理程度。

三种任务测量的心理构念并不完全相同。固定双分界最适合比较边界位移；自由分界同时测量阶段数量与位置；预设评价测量对外部方案的接受度。正式分析不应把三种主响应直接混为同一指标。

### 2.3 时间分辨率

- 日频；
- 周频；
- 月频；
- 年频。

分辨率在会话开始前锁定。这样避免参与者通过来回切换分辨率获得额外信息，也使实验条件可复现。价格条件的线性 / 对数切换按用户要求在第三级披露后开放；系统把最终刻度与切换次数作为行为变量记录。

## 3. 四级信息披露

披露顺序固定，因为研究对象正是语义逐层进入后的修正轨迹。

1. 形状：只显示曲线、阶段色块和完成任务必需的分界交互；不显示名称、日期、单位或事件。
2. 身份：显示资产、指标名称、指标定义和一段中性资产背景。
3. 坐标：显示真实时间轴、单位、选定分辨率；价格条件解锁正常 / 对数价格。
4. 事件：在时间轴上标注事件编号，并显示日期、名称和中性说明。

界面在每次切换前显示独立披露弹窗，并用橙色边框标出新内容，降低“新增信息不明显”的风险。

## 4. 刺激与数据来源

### 4.1 价格

来源为 Li Blockchain 项目中的 CMC 原始日频 TSV。日频使用 `Open*`；周、月、年为自然日历区间内日 Open 的算术均值。这样四种分辨率来自同一基础序列，而不是四套不可比较的数据。

### 4.2 活跃地址

来源为 Coin Metrics Community API 的 `AdrActCnt`。定义为一个自然日内作为账本变更发起方或接收方出现的唯一地址数。高阶分辨率显示“日活跃地址数的区间均值”，不是对整周、整月或整年重新去重的地址数。

当前免费同口径覆盖只有 BTC 和 ETH。Coin Metrics 的完整目录虽列出 SOL 与 BNB Smart Chain，但请求需要额外凭证；旧 BNB Beacon Chain 的免费序列在 2019 年结束，不能冒充 BNB Smart Chain。第三版因此明确标记 SOL / BNB 不可用。若正式研究要求四链完整面板，应先取得同一供应商、同一定义的授权数据，再冻结新协议版本。

### 4.3 Google Trends

使用 Worldwide、Web Search 的加密资产主题，而不是歧义较大的普通关键词。Google Trends 是抽样、聚合和标准化指标，不代表绝对搜索次数，重复下载可能略有差异。

2018–2026 超过网页端单次原生周频窗口。冻结脚本使用两段重叠的多年度周频请求，各自通过全窗口月频锚进行重标定，对共享周取均值，最后把全序列峰值设为 100。月频和年频由冻结周频聚合。日频不插值，界面直接禁用。

### 4.4 事件

当前事件都有来源链接，但仍是预测试集合。确认性研究应由不知道曲线分界结果的独立编码者，依据预先定义的纳入规则挑选事件；事件数量、名称长度、正负价态、类型和时间密度都应尽量平衡。

## 5. 随机化与控制

- 在锁定“指标 × 任务 × 分辨率”后，只随机化资产顺序；
- 同一资产内部的四级披露顺序固定；
- 不预选信心、影响或合理性量表；
- 下一层沿用上一层的分界位置，使“移动”成为显式修正；
- 若主判断未改变，参与者必须主动确认维持原判断；
- 每轮提交后不可返回修改，防止看到后续信息后重写先前答案；
- 奖励页只反馈个人轨迹，不给出正确答案或群体比较，避免影响下一条曲线。

## 6. 记录字段

会话层记录：

- 人类 / Agent；
- 匿名编号、经验水平、Agent 模型名称；
- 指标、任务、分辨率；
- 随机资产顺序；
- 协议版本、开始和结束时间。

逐层响应记录：

- 刺激、资产顺序、披露级别；
- 分界点数量与每个分界点的索引、归一化位置和日期；
- 预设分界点；
- 合理性、信心和新增信息影响评分；
- 是否主动确认“未变化”；
- 判断依据标签和开放理由；
- 总作答时间、披露后首次交互时间、首次边界移动时间；
- 边界调整次数、价格刻度切换次数和最终刻度。

## 7. 推荐指标

### 7.1 固定双分界任务

对边界 (k\) 与披露层 (l\)，定义归一化位置 (b_{ikl}\in(0,1)\)。

- 单步位移：`Δb = b(l) - b(l-1)`；
- 绝对位移：`|Δb|`；
- 总上下文弹性：四层轨迹的绝对位移和；
- 方向：向前 / 向后 / 不变；
- 边界交叉不允许，因此第一、第二边界可分别建模。

### 7.2 自由分界任务

除边界位置外，还需分析：

- 分界点数变化；
- 新增或删除边界的概率；
- 阶段长度分布；
- 使用最优匹配或 Wasserstein 距离比较两个无序边界集合，避免仅按序号硬配对。

### 7.3 预设评价任务

- 合理性评分的逐层差值；
- 由“不合理”跨越中点到“合理”的转变概率；
- 评分变化与信心变化是否同向；
- 事件披露的边际效应。

### 7.4 人类—Agent 比较

建议使用分层模型，把响应嵌套在“参与者 / Agent 运行、资产、披露层”内。固定边界可使用线性混合模型或稳健回归；不变概率可使用混合效应 logistic 模型；合理性评分可用有序 logistic 模型。报告效应量和区间，不只报告显著性。

## 8. Agent 运行协议

Agent 条件必须锁定：

- 模型和版本；
- 系统提示、用户提示与输出格式；
- 图像尺寸、裁切和压缩方式；
- 温度、随机种子或重复运行次数；
- 每层只能获得当层允许的信息；
- 是否允许工具调用和外部检索；
- 每次运行是否保留前层对话记忆。

推荐每个条件运行多次，把“同一模型的随机运行”视为重复测量，而不是把一次输出当作稳定人格。

## 9. 正式研究前的必要工作

- 伦理审批、知情同意、退出与数据删除机制；
- 预注册主要假设、排除规则、事件集、模型与分析代码；
- 用预测试方差做样本量 / 功效分析；
- 检查曲线几何难度、事件数量和文本长度是否跨资产平衡；
- 增加伪事件、错位事件或隐藏资产身份的反事实对照；
- 对 Google Trends 重复抽样做敏感性分析；
- 若需要四链活跃地址，先取得统一授权数据，不能在确认性分析中混用供应商口径；
- 冻结网页构建、刺激 JSON 的哈希值、数据库迁移和 Agent 协议版本。

## 10. 当前状态

`context-elasticity-multimetric-v4` 是可运行的预测试协议。它已经解决多指标复用、三种任务、四级披露、时间分辨率、价格对数刻度、无默认量表、未变化确认、来源元数据和结构化落库，但仍不等同于已预注册、已获伦理批准的确认性实验。
