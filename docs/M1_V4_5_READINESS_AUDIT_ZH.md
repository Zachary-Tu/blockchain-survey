# M1 v4.5 实验就绪审计

审计日期：2026-08-27  
审计对象：人类 M1（六资产 × 七个累积披露状态 × 固定两个分界点）

## 1. 结论

当前版本可以开始开发团队内部的桌面端流程、可用性和数据库 pilot。该 pilot 应用于发现操作困难、估算时长与疲劳、验证逐页保存及导出，不应直接并入论文主分析。

当前版本尚不适合立即开展正式外部招募，也不适合直接估计 Human–Agent 差异。主要剩余风险是 G0 初始位置锚定、对“移动”的需求诱导、事件材料的语言与剂量混杂，以及服务端尚未逐项校验会话计划。

M1 当前最准确的研究对象是：

> 沿固定累积披露路径、以上一轮答案为锚点的阶段边界修正轨迹。

它不能在没有重复基线或其他对照条件时，把每层变化解释为某一种信息的纯因果效应。

## 2. 本轮已修复

- 不确定范围半宽允许从 0.000 到 0.200；0 表示只报告点估计，不表示绝对确定。
- 0 宽度在前端、API、数据库 JSON、CSV 和完整生命周期测试中均与未作答的 `null` 区分。
- 人类响应版本升级为 `v4.5-zero-width-enabled`；旧版 v4.4 仍保持原最低半宽，不会静默改变历史协议。
- M1 会话顶层保存实验协议，刺激数据协议另存为 `stimulusProtocolVersion`。
- 非负线性序列的纵轴下限不低于 0，并在所有披露层共用同一绘图几何。
- 参与者说明页不再列举尚未披露的信息类别。
- GI2 不再额外说明 Open/聚合方法，只披露时间、频率、刻度与单位。
- 当前分界点标签已移出 SVG 裁剪区；上一层位置在重合时仍有可见的橙色轮廓。

## 3. 已验证的数据链路

- 每个正式会话包含 6 × 7 = 42 个独立响应单元。
- 每页提交后立即写入 D1；已提交的中途数据不会因为后续退出而丢失。
- 完全相同的网络重试为幂等操作，不生成重复记录；已锁定答案以不同内容重提会被拒绝。
- 正常完成要求 42 条响应；完成后可分别导出会话/设备 CSV 与逐题响应 CSV。
- 响应表包含边界、上一层边界、区间、影响评分及 touched 标记、总时间、可见时间、后台时间、首次交互、调整次数和逐页视口。
- 会话表包含匿名编号、经验、资产顺序、设备类别、屏幕/视口、平台、语言、时区、触控与指针类型。
- 类型检查、生产构建、网页/API 测试和完整 42 页数据库—CSV 生命周期测试通过。

## 4. 正式采集前必须决定或修复

### 4.1 G0 初始锚定

G0 默认在 1/3 与 2/3 放置分界线并显示三段底色，参与者无需移动边界即可提交。这可能压低基线方差并把等分位置变成显著锚点。首选方案是 G0 从空白状态依次放置两个点；低改动方案是要求逐条主动确认并记录两条边界是否被操作。

未回答的不确定范围目前视觉停在 ±5%，也可能形成范围锚定。正式版应隐藏未作答旋钮位置，或先让参与者选择“仅点估计 / 给出范围”。

### 4.2 更新诱导与影响评分

保持边界不变需要额外勾选，而移动不需要，操作成本不对称；影响评分又在边界锁定前可见。这可能系统性夸大上下文弹性。正式版应采用对称确认，并在锁定边界后再显示影响评分。

影响评分视觉默认 3，但 `influence_touched=false` 时不应解释为真实中等影响。若保留当前交互，分析中必须把未触碰的默认值视为缺失。

### 4.3 事件材料

DI3/DI4 当前为英文新闻文本，存在长度、语气、日期可靠性和直接复述价格涨跌等差异。中文人类与 LLM 的比较会混入英语阅读能力。正式版需要冻结经人工复核的中性中文或双语摘要，核验日期与来源，尽量统一信息量，并排除直接陈述价格结果的材料。

每层“最多 10 个”当前指新增事件；DI4 可能同时显示 DI3 保留的 10 个和新加的 10 个。需要明确限制究竟针对新增数还是总可见数，并解决密集标签重叠。

### 4.4 服务端实验完整性

正式远程采集前，服务端应根据会话中的冻结计划逐项校验 trial、资产、顺序、披露键、条件和上一层答案，而不只是检查总行数；已完成会话必须禁止继续写入；空或无效计划不能完成。公开入口还需要服务端固定配置或签名启动令牌，避免客户端伪造实验分组。

当前刷新后不能续答：已提交页面仍保存在数据库，但未提交页面及浏览器进度会丢失。内部 pilot 可将其视为中断；正式远程实验应增加恢复机制或预先冻结排除规则。

## 5. pilot 中应重点观察

- 六名开发者或少量内部参与者完成 42 页所需总时长、中途退出率和后半程响应时间增长；
- G0 保留 1/3、2/3 默认位置的比例，以及 5% 默认范围附近的聚集；
- 0 宽区间的选择比例。分析时分别建模“是否选择 0”和非零宽度，不直接对宽度取对数；
- 电脑端拖动精度、误触、零宽选择是否容易，以及上一层线与当前线是否可辨认；
- DI3/DI4 的阅读负荷、事件标签重叠和不同资产事件数量差异；
- `influence_touched=false` 的比例；
- 中断会话、重复匿名编号、网络重试和 CSV 中 42 行完整性。

手机端尚未完成真实触控审计。第一轮科学 pilot 建议统一使用桌面视口；手机可在后续作为独立稳健性条件。

## 6. 0 宽度的分析约定

- `null`：范围回答未完成；
- `halfWidthRatio = 0`：明确只报告当前分界点；
- `widthRatio = 0`：完整区间宽度为 0；
- `halfWidthRatio > 0`：相对于整条显示时间窗的单侧半宽；
- 跨资产比较时，除比例外应换算为观测点数或实际周数，因为各资产完整历史长度不同；
- Agent 高频选择 0 不能自动解释为校准更好。

## 7. 放行状态

| 用途 | 状态 | 条件 |
| --- | --- | --- |
| 开发团队 UI/数据库 smoke test | GO | 可立即开始 |
| 受控桌面可用性 pilot | GO | 数据仅用于发现问题，不进入主分析 |
| 用于估算正式效应量的 pilot | CONDITIONAL | 先处理 G0/范围锚定与影响评分解释 |
| 正式外部人类采集 | NO-GO | 先完成事件材料、服务端计划校验与恢复/排除规则 |
| 正式 Human–Agent 比较 | NO-GO | 另需统一视口、平衡顺序、冻结模型元数据，并限制 Agent 只能使用渲染页面与同等交互 |
